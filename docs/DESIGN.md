# 工具设计规范 · DESIGN

> 维护工具时遵循的统一标准，保证三件套风格一致、可持续迭代。

---

## 设计原则

1. **单文件优先**：每个工具是一个独立 HTML，无需安装、无需联网、手机直接打开
2. **离线可用**：数据存浏览器 localStorage，现场没网也能用
3. **零学习成本**：填空 + 点选为主，老师傅也会用
4. **一键导出**：调研完直接产出 Markdown，不用回去重新整理

## 配色规范

| 角色 | 色值 | 用途 |
|---|---|---|
| navy | `#1A2B4A` | 主色、顶栏、标题 |
| navy-2 | `#2C4870` | 渐变辅助 |
| gold | `#E89B3D` | 强调、按钮、选中态 |
| gold-l | `#F5D89C` | 浅金、标签 |
| cream | `#FBF5E9` | 卡片背景 |
| green | `#10B981` | 满足 / 正向 |
| amber | `#F59E0B` | 边缘 / 警示 |
| red | `#C13C2E` | 不足 / 高风险 |

字体：系统默认 + 微软雅黑

## 数据结构约定

localStorage key 命名：`{tool}_survey_v{n}`
- `warehouse_survey_v2` — site_survey
- `liugong_deep_survey_v1` — deep_survey

state 结构统一为：
```js
{
  meta: {},      // 调研元信息
  values: {},    // 文本/数字输入
  picks: {},     // 单选
  multis: {},    // 多选
  pcts: {},       // 百分比滑块
  sevs: {},       // 严重度评分
}
```

## 兼容性注意

- **微信内置浏览器会拦截原生 `confirm()`** → 必须用自定义确认弹窗
- iOS Safari 的 `env(safe-area-inset)` → 底部按钮要留安全区
- 数字输入框用 `inputmode="numeric"` → 手机弹数字键盘

## Markdown 导出规范

- 报告头：客户名 + 调研日期 + 调研人
- 分 Part 组织（与 Tab 对应）
- 结尾必带"自动洞察段"——基于填写数据自动生成关键发现
- 数字缺失用 `—` 占位，不留空

## 自动洞察规则示例

```
if JIT 占比 >= 50% → "JIT 节拍是核心 KPI"
if 拣货走动 >= 35% → "货到人 AMR 价值突出"
if WMS 缺 >= 3 项功能 → "WMS 需升级或替换"
if 与客户对接靠人工/Excel → "必须建 MES 直连"
```
