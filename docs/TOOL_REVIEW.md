# 三件套工具评估 · TOOL REVIEW

> 对照 PLAN「回顾三件套工具，记录哪些好用 / 哪些不好用」。
> 方法：通读三个工具源码 + 结合柳工实战。结论按"好用 / 不好用 / 发现的问题 / 改进建议"组织，末尾给 v1.0 升级优先级。
> 评估日期：2026.05 · 版本：升级后（含行业模板 / 投资测算器 / 订单口径校验 / 数据打通）

---

## 1. site_survey.html（现场物理 + 机会评分）

**好用**

- 7 维评分 + 物理 5 大约束分组（含"业主方改造许可"），覆盖完整，新人照着填不会漏。
- 自动选型提示 + 投资分层建议，把老顾问的判断固化进工具。
- localStorage 自动保存、微信兼容的自定义确认弹窗，现场离线可用。
- 新增：行业模板切换（4 行业）、满分与导出表列随维度动态生成。

**不好用 / 局限**

- 工位推荐用 `name.includes('拣货')` 这类关键词匹配 → 工位名不含特定词就落到"需详细方案讨论"，自定义工位命中率低。
- 切换行业模板后，旧维度的已打分数仍留在 `state.scores`（无害，但不在新模板导出里体现），用户可能困惑。

**发现的问题（应修）**

- ⚠ 导出报告标题硬编码「柳工配件库智能化升级」（site_survey.html 现仍出现"柳工"3 处）→ 换客户用就不对了。
- ⚠ 无「客户名」元信息字段，报告头缺客户名。

---

## 2. deep_survey.html（系统 / 订单 / 流程）

**好用**

- 三 Tab（订单流程 / 系统现状 / 异常访谈）结构清晰，数据拉取清单按优先级排序很实用。
- 滑块百分比 + 严重度评分 + 三角色访谈卡（含金句收集），软性信息也能结构化。
- 新增：订单口径校验——填「件/单 < 行/单」「峰 < 均」等不合理值会实时预警，直接落实经验 2/3。

**不好用 / 局限**

- 案例特定文案混进通用工具：placeholder / card-hint 里出现「五菱」10 处、「松芝」1 处、具体单据数字 → 换客户看着突兀。
- 数据拉取清单等文案偏柳工场景，跨行业时部分项不适用。

**发现的问题（应修）**

- ⚠ 导出报告标题硬编码「柳工配件库 · 系统/订单/流程 深度调研报告」。
- ⚠ 无「客户名」字段。
- 建议把"五菱/松芝/具体数字"等案例文案抽成中性提示。

---

## 3. layout_solution.html（方案可视化）

**好用**

- SVG 平面布局 + 四区详解 + 投资矩阵 + 分期 + ASRS/Shuttle 选型对比，客户看着专业。
- 新增：投资测算器（改 SKU/面积自动重算）+ 数据假设与置信度段，从纯静态变可交互。

**不好用 / 局限**

- 本质是「柳工案例的方案样板」而非空白模板：硬编码"柳工"21 处、五区分区与设备清单全是柳工的。换项目要大量手改 HTML。
- 与 `cases/liugong/03_方案文档.html` 内容高度重叠（仅 ~80 行 diff），工具版与案例版边界模糊。
- 除测算器外无交互，分区/设备/投资都要改源码。

**发现的问题（应修 / 决策）**

- 需明确定位：① 改造成「空白可填模板」（字段化，表单驱动生成方案）；或 ② 明确标注它是"样板范例，复制后手改"，并与案例版去重。

---

## 4. 共性问题（三件套通用）

1. **客户名缺失 + 标题硬编码柳工** — 最影响"可复制到其他项目"。建议统一加 `客户名` meta 字段，报告标题用 `${客户名} · xxx报告`。
2. **案例文案与工具混用** — 五菱/松芝/柳工等具体内容应抽成中性占位或示例标注。
3. **localStorage key 各自独立** — 已能通过统一 JSON 包合并导出打通，但仍无跨工具自动跳转 / 共享客户名。
4. **layout 工具定位** — 静态样板 vs 可填模板需拍板。

---

## 5. v1.0 升级优先级建议

| 优先级 | 事项 | 工具 | 工作量 |
|---|---|---|---|
| P0 | 加「客户名」meta 字段，报告标题去硬编码 | 三件套 | 小 |
| P0 | 清理案例特定文案（五菱/松芝/具体数字）为中性 | deep / layout | 小-中 |
| P1 | 工位推荐从关键词匹配改为可选标签/下拉 | site | 中 |
| P1 | 跨工具共享客户名 + 元信息（一次填多处用） | 三件套 | 中 |
| P2 | layout 定位拍板：空白可填模板 or 样板范例去重 | layout | 大 |
| P2 | 行业模板联动物理约束 / 数据拉取清单 | site / deep | 中 |

> 建议下一轮先做 P0（半天内可完成，立刻提升"可复制"程度），P1/P2 结合团队试用反馈再排期。
